## 二、P0 移动端：三个「看不到」

### 2.1 没有导航（最致命）

`SiteHeader.astro` L21：`<nav class="ml-auto hidden items-center gap-5 sm:flex">` —— 640px 以下整条导航 `display:none`，且**没有汉堡菜单、没有抽屉**。手机用户只能点左上角 logo 回首页，其余 8 个模块（Hot200 / 项目 / 实习 / MySQL / 中间件 / AI / 训练场 / 评审）**没有任何入口**。

实测（390px）：`/`、`/hot200`、`/hot200/lc1`、`/mysql/mysql-02`、`/project` 全部「可见导航链接 = 0」。

### 2.2 Hot200 看不到参考代码

`hot200/[slug].astro` L324：`<aside class="hidden w-[440px] … xl:block …">`。1280px 以下整块消失，**连折叠按钮都没有**。手机上只剩题面、示例、讲解（讲解里有零碎 snippet，但不是完整参考代码）。

同理 `QuestionDetail` 左侧题目目录 `hidden lg:block`（1024px 以下消失），`DocReader` 文档目录 `hidden`（<lg 消失）——长文（实测 `/mysql/mysql-02` 手机高度 4138px）没有目录，只能盲滑。

### 2.3 四个页面横向溢出（能左右拖，体验崩）

| 页面 | 文档宽 | 视口 | 溢出 |
|---|---|---|---|
| `/` | 470px | 390px | +80px（`<section>` 内 grid 没塌陷，实测 446px 宽） |
| `/project` | 455px | 390px | +65px |
| `/review` | 574px | 390px | +184px |
| `/errors` | 574px | 390px | +184px |

`/hot200`、`/notes`、`/ai`、`/mw`、`/train`、`/intern` 等**没有**溢出（375px），说明只是少数页面的 grid/表格写死了宽度。

### 2.4 批注在触屏上的兜底

`Annotations.astro` L1004 只监听 `mouseup`，没有 `touchstart/touchend/pointerup` 兜底。触屏长按选中后能否弹出工具条**未在真机验证**（代码层面没有保证），这是「手机上标注」的主要风险点。

### 修复清单（都不大）

1. 顶部加汉堡 → 抽屉（`<button>` + 全屏 nav，`<details>` 或 JS 二选一）
2. Hot200 在 `xl` 以下渲染一个 `<details>「查看参考代码（N 行）」` 折叠块，内容复用现有 `.code-line` 渲染（多解法 tab 也要一起可用）
3. 4 个溢出页面：外层 + `overflow-x:auto` 容器并加「← 左右滑动 →」提示，或把固定宽度 grid 改成 `grid-cols-1 sm:grid-cols-2`
4. 批注补 `pointerup` + `selectionchange` 防抖

## 三、P0 信息检索：找不到东西

现有搜索的实现是 `/project/find.astro`：把 355 条题目标题/标签序列化成 `<script type="application/json" id="search-data">`，客户端做子串+高亮过滤。**这套方案很好，但只覆盖了 355 题**，而且 `/project/search` 不是搜索（是「搜索模块」的文档，标题为「搜索模块 · 项目经历」，8 条内容）。

缺口：

- Hot200 103 题 **无搜索**（只有 category chip + 「只看没写讲解」）
- Java 基础 58 题 **无搜索**
- 训练场 103 题 **无搜索**
- 181 篇文档 **无全文搜索**
- **没有全站搜索入口**（首页、顶栏都没有）

建议：新增 `/search`，复用 find 的 JSON+d高亮方案，索引 = 516 题（标题/标签/一句话/分类）+ 181 篇文档（标题/小标题）。体积估算：355 题时 payload ≈ 190KB gzip，全量约 260KB gzip —— 偏重，**建议按模块懒加载**（首屏只带标题，输入后再加载正文），或分片成 `/search/index.json`（按关键词哈希分片）按需 fetch。

> 约束：npm 不可用（内网 Artifactory 没 pagefind），所以只能自建索引，不能引 Pagefind；这点和当初 Mermaid 只能本地 vendor 是同一个坑。

## 六、P1 工程坑（直接影响真实用户）

1. **`http://127.0.0.1:4400` 硬编码在 6 处**：`Annotations.astro`、`ContentEditor.astro`、`InternEditor.astro`、`ModuleGraph.astro`、`UsageTracker.astro`、`index.astro`。手机访问 → 请求打到手机自己 → 批注同步、复习记录、使用统计全挂，控制台报错。建议：改同源 `/api/...`（部署时反代），并**失败静默降级**（现在至少要有 catch）。
2. **无 404 页**（`src/pages/404.astro` 不存在，`/errors` 是另一回事）、**无 robots.txt / sitemap.xml**、**无 OG/Twitter 卡片**（`BaseLayout` 只有 title + description）→ 分享到微信/飞书就是白板链接，搜索引擎也不收录。
3. **同一题两条 URL，批注互不可见**：`/mysql/mysql-02` 与 `/project/mysql/mysql-02` 同时存在（内容仅面包屑不同），而 `Annotations` 用 `const PAGE = location.pathname` 做键 → 在一条 URL 上标注，另一条看不到。46+48+68+103 题都受影响。建议：批注键改用 `canonical`（数据里的稳定 id），并给 `/project/*` 加 `rel=canonical` 指向模块页。
4. **孤立页**：`/about` 入链 0、`/hot200/review` 入链 0、`/roadmap`、`/scores` 各 1 条入链 —— 用户基本不可能发现。
5. **重页**：`/project/find` gzip **190KB**、`/project/flashcards` **168KB**、`/project/sheet` 77KB（全量 JSON 内联）。对比：Hot200 详情页 11KB、CSS 14KB。建议 find/flashcards 改按模块分片加载。
6. **Mermaid 2.5MB 只服务 8 个页面**（`/ai/read/ev-01` 等）→ 该 8 页首屏要拉 2.5MB，建议按需 `import()` 或改成服务端预渲染 SVG。
