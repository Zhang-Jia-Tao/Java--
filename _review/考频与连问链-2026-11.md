# 考频榜与连问链（2026-11）

> 目标：秋招/春招面试的短板不是「题不够」，是「不知道背哪些」和「面试官一追就崩」。所以先分考频，再只给高频题写连问链。

## 一、为什么先做考频，而不是给每道题加连问链

516 题全部加连问链是无效功：一是工作量爆炸，二是绝大多数题面试根本不问。现有 A–E 评分衡量的是「稿子写得好不好」，与「面试考不考」无关，两者混用会让人误以为高分题就是必背题。

所以拆成两步：

1. **考频分档**（`src/data/freq.json`）：确定背哪些；
2. **连问链**（`src/data/chain/*.json`）：只给 S 级里最高频的题做「被追问」训练。

## 二、考频怎么分的（可解释，不是黑箱）

`site/scripts/gen-freq.mjs` 生成 `site/src/data/freq.json`，三档 + 一个不参与：

| 档 | 判定 | 数量 |
|---|---|---|
| S 必背 | 手排清单（每题一句理由），Java 后端校招必问 | 33（Java 线）+ 4（AI 线） |
| A 常考 | 标题命中高频考点词表（索引/事务/锁/MVCC/JVM/线程池/Redis/MQ/分布式/TCP/HTTP…） | 129 + 29 |
| B 会问 | 八股池里其余题 | 93 + 35 |
| — | 个人项目 90 题（面试问不问取决于简历）、Hot200 103 题（手撕按精刷路线走） | 193 |

覆盖口径：Java 58 + MySQL 46 + 中间件 48 + 训练场 103 + AI 68 = 323 题进考频；页面明确写了「这是编辑判断，不是抽样统计」，避免把主观分档伪装成数据结论。

一致性保护：`node scripts/gen-freq.mjs --check` 会比对现有 `freq.json` 与重新计算的结果，防止改了题目忘了重算。

## 三、连问链的数据结构

`site/src/data/chain/<题目id>.json`，一条链 = 5 层追问：

```jsonc
{
  "id": "1-1",
  "title": "HashMap 与 ConcurrentHashMap 区别",
  "module": "Java 基础",
  "href": "/notes/ch1/1-1",
  "why": "为什么这题值得做链",
  "layers": [
    {
      "q": "面试官第 1 层追问（原话）",
      "a": "满分回答：3–5 句，能直接说出口",
      "trap": "这层在考什么 / 答错会怎样",
      "pass": "答到什么程度算过"
    }
  ],
  "perfect": { "text": "整条链的 2 分钟满分总答", "note": "答题提醒" }
}
```

关键设计：**每层都有 `trap` 和 `pass`**。只给答案的链还是「读」，给了「坑」和「过线标准」才是「练」——练习者能自己判断要不要重来。

已覆盖 12 题 / 60 层：HashMap 与 CHM、HashMap 原理、synchronized vs ReentrantLock、线程池、Bean 生命周期、循环依赖、B+ 树、MVCC、Redis 持久化、分布式锁选型、缓存三兄弟、TCP 三次握手。

## 四、连问链放在哪里：候选与结论

| 方案 | 优点 | 问题 | 结论 |
|---|---|---|---|
| A. 详情页正文中部 | 阅读时顺路看到 | 打断「答案 → 追问 → 改法」的阅读节奏；**更严重**的是 ContentEditor 按 DOM 子节点索引存改稿，中间插块会让后面所有元素的索引整体位移，已存的批注/改稿会错位 | 否 |
| B. 详情页顶部 tab 切换（答案 / 连问链） | 一页内完成 | 要改详情页骨架，风险大；阅读与训练混在一起，读答案时总被「练」打断 | 否 |
| C. 独立训练页 `/chain/[id]` | 能承载训练需要的一切：计时、逐层揭示、崩在第几层、复盘记录 | 与题目页割裂，需要入口 | **采纳（训练）** |
| D. 详情页文末小块折叠/入口 | 不打乱阅读，不动已有 DOM 索引（追加在 `<main>` 最后一个子节点） | 不承载训练 | **采纳（入口）** |
| E. 只放在考频榜里 | 实现最省 | 发现性差，背题时不会主动去榜里找 | 否 |

最终形态是 **C + D 组合**：

- **详情页文末**（`ChainTeaser.astro`）：显示考频档 + 一句「为什么是高 freq」+ 第 1 层追问 + 「逐层练这 5 层 →」。放在 `<main>` 末尾（Java 基础页在 `PrevNext` 之后），保证不改变前面任何元素的 DOM 索引，已存批注与改稿不受影响。
- **独立训练页** `/chain/[id]`：一次只显示一层，先答再看参考，展开后给「这层在考 / 过线」；走完出 2 分钟满分总答；最后自评「崩在第几层」，写 `localStorage`（`dsh:chain:<id>`），下次进来先显示上次成绩。
- **入口三处**：顶栏「考频」→ `/freq` 榜 → 行尾「连问链 →」；详情页文末块；页脚「连问链训练」。`/chain` 列表页给出 12 条链与练法。

## 四之二、为什么默认只露第一层，以及怎么避免「只有一层」的误解

逐层揭示是训练模式的必要条件：一次看到全部 5 层，人会直接往下读，等于又变成「读」。
但上线后发现两个发现性问题，已修：

1. 训练页顶部加了 **5 层目录**（只列问题、不露答案），可以点 `L1–L5` 直达任意一层，URL 带 `#L3` 也能直接打开；
2. 训练页 sticky 栏加了 **「看全部 5 层」** 开关：打开就是只读模式（5 层全露、答案全开、总答出现），再点一下回到逐层练；
3. 详情页文末的入口不再只写「第 1 层」，而是把 **5 层的问题全部列出来**（答案仍在训练页），并注明「上面是 5 层的问题」。

判定依据不是猜的：用 CDP 真点了一遍，初始 1 层可见 / 点「看全部」5 层全开 / 点目录 L4 直接到第 4 层（前 3 层答案已开）/ `#L4` 哈希一致。
## 五、实测（2026-11-03）

- 构建 1106 页（+14：`/freq`、`/chain`、12 条链），sitemap 839 条。
- `/freq` 默认 S 视图渲染 37 行、12 个「连问链」入口；客户端筛选（档位 / 领域 / 只显示有链 / 关键词）正常。
- `/chain/1-1`：5 层，首层可见、其余 4 层 `display:none`，满分区默认收起，计时器 00:00 起算。
- 详情页：`/notes/ch1/1-1`、`/mysql/mysql-19`、`/mw/redis/redis-15`、`/train/scenario/sc-06` 均出现「面试考频 + 连问链 5 层」；`/mysql/mysql-01`（B 档）只显示考频、提示暂无链；Hot200 与个人项目页不显示（不参与考频）。
