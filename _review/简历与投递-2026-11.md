# 简历怎么用 + 投递台账（2026-11）

> 对象：张佳涛简历 (8).pdf（2027 届，后端 + AI 应用）。**海康实习一段以站内《实习期开发任务全记录》与 /intern 为准，本文不采用简历 PDF 的旧版本。**

## 一、简历的定位：它是「钩子」，不是「总结」

简历只有一页，面试官不会从头读到尾。他做的是「扫一遍 → 挑一条最像岗位的 → 从这句话切进去追问」。
所以简历的每条 bullet 都必须满足：**能被追问 3 层还不崩**。崩在哪一条，就说明那一条你其实没做过。

站内 355 道项目题 + 37 条连问链就是为这个准备的弹药。映射关系落在 `/resume` 页：每段经历 → 对应题（带 S/A 档与「链」标记）→ 面试可能从哪儿切进来。

## 三、五条使用法

1. **一段经历 = 3–5 道题**：`/resume` 页每段的 map 就是这个对应关系。面试官从简历哪句话切进来，你就知道从哪道题、哪条链开始答。
2. **按岗位做两版**：后端岗（海康第一段、券享购第二段、Zragent 压后）；AI 岗（Zragent + BR-SFDA 提前，海康一行）。投递台账里记下用的是哪一版。
3. **数字必须可回溯**：站内 metrics 与对应题都写了口径，答不出就删数字，别赌。
4. **海康换成站内最新口径**：时间对齐 08-11~10-28，模块名对齐「配单平台」，挑 3 个能讲透的（+24 缺陷、SPS 卡死、服务器替代链）。
5. **先投合适的，再谈补齐**：2026-11 秋招已近尾声 → 接下来是补录与春招。补录偏「即插即用」（技术栈要显眼），春招国企/银行更看基础与笔试（论文 + 国奖往前放）。

## 四、投递台账 + 复盘闭环（/apply）

数据模型（localStorage `dsh:apply:v1`）：

```
{ items: [{ id, company, role, channel, date, stage, failAt, review[], questionIds[] }], done: [题目 id] }
```

闭环链路：

1. 投一家记一家（公司/岗位/渠道/日期/状态）；
2. 面试后 30 分钟内写三条复盘（考了什么 / 哪句崩了 / 下次怎么说）；
3. 把答崩的题从 S 级必背里勾上（37 题可选）；
4. 状态为「已挂」时，关联题自动进「待补清单」；
5. 补完勾掉，去 `/chain` 把那一题练到能连过 5 层；
6. 可导出/导入 JSON，换机或清缓存前留底。

实测（CDP 真点）：填表保存 → 投递 1 / 进面 1 / 已挂 1 / 待补题 1；待补首行是「HashMap 与 ConcurrentHashMap 区别 · 练链 → · 已补」；点「已补」→ 待补 0；导出/编辑按钮可用。

## 五、和站内其它页的关系

- `/freq` 考频榜：决定「背哪些」；
- `/chain` 连问链：决定「能不能扛住追问」；
- `/resume` 简历映射：决定「面试从哪切进来」；
- `/apply` 投递台账：决定「下一轮先补什么」；
- 四者共用同一套题目 id，复盘挂掉的题会直接指回前三个页面。

## 六、还没做

- 简历本身没改（我不动用户 PDF）：`/resume` 只做了映射与体检，重写建议要用户确认口径后落到文档；
- 投递台账没有云端同步（纯 localStorage），多设备要导出/导入；
- 没有「按岗位自动生成简历重点清单」——映射是手工维护的 `resume-map.json`；
- 没有接日历/提醒（投递后 7 天没回复该催一下这类）。
